## 2. 结论

V2 的判定接口已经能接住旧插件：`POST /api/open/decision` 仍可用 `X-API-Key`，返回里仍有 `page=review|real`。密钥必须是站点的 `sk_`，V1 单独签发的 `ck_` Token 不能直接用。

V2 新插件还没有做完 V1 接入文档里的展示方式。V1 的审核页和真实页各自都能选四种输出：站内页面跳转、外部链接跳转、HTML 文件地址跳转、PHP 直接输出。V2 新插件只配置审核页，而且都在当前地址以 200 输出；放行后就是继续渲染访客正在打开的页面，不能再指定另一套真实页。

本方案把 V1 的八种输出（审核四套、真实四套）补进 V2 插件，同时把「同一个链接、地址不变、返回不同页面」做成默认和推荐路径。跳转保留，给已经按 V1 上线的站点用。新站点默认不跳转。

## 3. 要解决的问题

商户从 V1 过来时，接入文档按「跳转到审核页或真实页」来写。广告链接、落地页路径、站内统计都绑在原来的地址上。302 一跳，地址变了，回访和跨浏览器交接也断了。

V2 已经能在当前地址返回两套内容，但接入指南只写了两段摘要，没有按场景告诉商户该选哪一种、后台点哪里、页面上会看到什么。V1 文档有方案一到方案三和插件说明，V2 反而更短，商户对不上。

## 4. V1 接入方式（必须保留）

来源是 V1 教程第 5 节和 `cloak-api` 的 `review_mode` / `real_mode`。审核页、真实页使用同一组模式。

| 模式 | 代码值 | 访客看到的地址 | 插件怎么做 |
| --- | --- | --- | --- |
| WordPress 站内页面 | `wp_page` | 变成目标页面的固定链接 | `wp_safe_redirect` 302 |
| 外部链接 | `external_url` | 变成外部 https 地址 | 域名在白名单内才 `wp_redirect` 302 |
| 服务器 HTML（URL 跳转） | `html_redirect` | 变成 HTML 文件的公开地址 | 302 到该 URL |
| 服务器 HTML（直接输出） | `html_output` | 保持访客打开的地址 | 读文件，200 输出后结束请求 |

另外这些行为也要保留：全站或仅首页、排除路径、接口失败时显示审核页或真实页、跳过后台 / Ajax / Cron / REST、外部链接只允许 https。

判定请求仍是服务端发起。Token 只放在 `wp-config.php` 或环境变量，不进前端。

## 5. V2 现状

| 能力 | 现状 |
| --- | --- |
| 旧判定接口 | `POST /api/open/decision`，`X-API-Key` 比对站点 `sk_` 明文，响应补 `page`、`action` |
| 新判定接口 | `POST /api/open/v2/decision`，签名。`content` 为 `real` / `bypass` 放行，其余走审核。审核时带 `renderHint`（`html` / `url` / `static` / `none`） |
| 托管接入 | 域名解析到网关。同一 URL 回源真实源站，或返回平台模板、审核源站、静态包。地址不变。不需要插件 |
| 新插件审核输出 | 平台模板、当前地址渲染站内页面、读 HTML 文件、服务端拉取外部地址后输出。注释写明不跳转 |
| 新插件真实页 | 没有 `real_mode`。放行就 `return`，WordPress 继续渲染当前请求 |
| 从 V1 设置迁移 | 站内页面、HTML 直接输出、外部链接会迁到上面三种同域输出。HTML 的 URL 跳转只有在填了文件路径时才变成直接输出。真实页的模式不迁移 |
| JS SDK | 两套内容都在浏览器里，只切换显示。不能当作严格隐藏 |

## 6. 产品原则

1. 同一个链接返回不同页面，是默认能力。地址栏保持访客打开的那个 URL，状态码 200。
2. V1 的 302 全部保留，作为兼容模式。配置项名称和 V1 对齐，老站点打开插件就能对上原来的选项。
3. 审核页和真实页分开配置。真实页默认是「继续当前页面」，这是 V2 比 V1 少一步的地方：不必再为真实内容单独建一个页面。
4. 托管接入优先于写代码。网站已经有源站时，用域名和站点配置完成双内容，不装插件。
5. 接口失败默认审核内容。商户可以改成真实内容。
6. HTML 不进全页缓存。文档和插件说明里写死这条。

## 7. 目标能力

### 7.1 输出模式

审核页、真实页各自五种。前四种与 V1 同名同行为，第五种是 V2 默认。

| 模式 | 审核页 | 真实页 | 地址 |
| --- | --- | --- | --- |
| 继续当前页面 | 不适用。没有归因时必须换成审核内容 | 默认。继续渲染访客打开的这篇 | 不变 |
| 平台模板 | 默认。用站点里配置的模板、审核源站或接口返回的 HTML | 不适用 | 不变 |
| 站内页面，当前地址渲染 | 在当前 URL 渲染所选页面 | 在当前 URL 渲染所选页面 | 不变 |
| 服务器 HTML，直接输出 | 读路径，200 输出 | 读路径，200 输出 | 不变 |
| 外部地址，拉下来输出 | 服务器请求该 URL，把正文输出到当前地址 | 同左 | 不变 |
| 站内页面，跳转 | 302 到该页面固定链接 | 302 到该页面固定链接 | 变 |
| 外部链接，跳转 | 302，https，主机在白名单 | 同左 | 变 |
| HTML 文件地址，跳转 | 302 到文件的公开 URL | 同左 | 变 |

新安装默认：审核页用平台模板，真实页用继续当前页面。从 V1 迁过来的站点保持原来的模式，不偷偷改成不跳转。

### 7.2 比 V1 更方便的地方

| V1 | V2 |
| --- | --- |
| 先建 API Key，复制 `ck_`，再写死接口地址 | 站点创建时给出 `sk_`。插件里填网关地址和这一把密钥，可点「测试连接」 |
| 审核页、真实页都要选一种输出，真实内容常常还要再建一个页面 | 真实页默认就是当前站点。只准备审核内容 |
| 教程把跳转写在前面，同域输出是 5.5.2 和 5.6 的可选项 | 接入指南按场景开头。地址不变的做法放在前面，跳转单独标成「地址会变」 |
| 审核页内容在 WordPress 或 HTML 文件里维护 | 平台模板、审核源站、静态包在商户后台改，插件选「平台模板」即可，不用发版 |
| 判定只看当时的 IP、UA、Referer | 同一访客写 Cookie。带参首访放行后，同一浏览器再打开不带参数的链接仍是真实页 |
| 内置浏览器和系统浏览器各算各的 | 站点打开提示条后，内置浏览器里给出「打开」，系统浏览器能接上同一次访问 |
| 全页缓存靠商户自己记得关 | 同域输出的响应带 `Cache-Control: no-store`。文档把 WP Rocket、LiteSpeed、Nginx 写成必做项 |

托管接入是插件之外的一条路：域名指到网关，真实源站和审核内容都在站点配置里。访客打开的仍是商户域名。V1 没有这条。

### 7.3 不改变的部分

斗篷列表的短链跳转保持独立。短链本来就会离开 `/c/{code}`，不属于同域双内容。

判定规则仍用 V2 的归因参数、分销码和回访，不把 V1 斗篷的地区、来源、屏蔽 PC 再做回站点判定的主线。那些留在斗篷列表。

## 8. 接入文档要怎么写

商户端「接入指南」里的「同域双内容」改成场景，不再只有两段摘要。完整稿见 `integration-guide-dual-content.md`，落地时按该结构改 `frontend/src/views/merchant/api-guide`。

场景顺序：

1. 先选场景：一张表，按「要不要改网站代码、地址变不变」选。
2. 场景一，托管接入。后台点哪里，访客打开后发生什么。
3. 场景二，WordPress 同域双内容。插件四种不跳转的审核输出，逐步配置。
4. 场景三，自研服务端。判定、写 Cookie、按 `content` 输出，附 PHP 最小示例。
5. 场景四，兼容 V1 的跳转。审核页和真实页的三种 302，写明地址会变，以及什么时候才该用。
6. 场景五，JS SDK。写明两套 HTML 都会下载到浏览器，严格隐藏不要用这条。
7. 上线前检查：密钥、缓存、排除路径、失败兜底、怎样看调用日志。

每个场景都包含：适合谁、准备什么、操作步骤、访客看到什么、不要做什么。

## 9. 验收

1. 新插件里，审核页和真实页都能选到第 7.1 节的对应模式。默认值是平台模板和继续当前页面。
2. 四种不跳转模式的响应是 200，浏览器地址栏与访客输入的地址一致。
3. 三种跳转模式的响应是 302，目标与 V1 插件一致：站内固定链接、白名单内的 https、HTML 的公开 URL。
4. 外部链接不是 https，或不在白名单，不跳转。
5. 排除路径、后台、Ajax、Cron、REST 不判定。
6. 网关超时或返回错误时，按失败策略输出审核内容或真实内容。
7. 旧 `cloak-api` 用站点 `sk_` 调 `POST /api/open/decision`，仍能读到 `page`。
8. 接入指南按第 8 节的六个场景展开，商户不看代码也能完成场景一和场景二。

## 10. 本阶段不做

不改判定引擎，不改斗篷短链，不把 `ck_` 独立 Key 重新做回来，不在这个文档里改商户端页面。页面改动跟开发一起做。

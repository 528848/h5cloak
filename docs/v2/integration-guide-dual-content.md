# 同域双内容接入指南

这篇按场景写。先看选择表，只做对应的那一节。地址栏保持不变的做法在前，会跳转的做法单独放在场景四。

判定结果只有两类需要商户处理：

| 返回 | 含义 | 页面 |
| --- | --- | --- |
| `content` 为 `real` 或 `bypass` | 放行 | 真实内容 |
| 其他，含 `review` | 不放行 | 审核内容 |

旧插件只读 `page`：`real` 是真实页，`review` 是审核页。新接口同时给出这两个字段。

## 先选场景

| 你的情况 | 用哪一节 | 地址栏 | 要不要改网站代码 |
| --- | --- | --- | --- |
| 网站已经在一台源站上，希望访客仍打开你的域名 | 场景一 托管接入 | 不变 | 不用 |
| WordPress，希望同一个链接看到两套内容 | 场景二 插件，不跳转 | 不变 | 不用，只装插件 |
| 自研 PHP、Node 或其他服务端 | 场景三 | 不变 | 要，在输出页面前加一段判定 |
| 已经按 V1 做了跳转，或审核页必须是另一个固定网址 | 场景四 | 会变 | 插件里改成跳转模式 |
| 一个静态 HTML，两套内容可以都下载到浏览器 | 场景五 JS SDK | 不变 | 改页面，不改服务器 |

接口失败时一律先显示审核内容。确认业务允许后再改成真实内容。

HTML 不要做全页缓存。WP Rocket、LiteSpeed、Nginx 的全页缓存会把第一个访客的页面发给后面所有人。同域输出必须排除前台，或按访客 Cookie 分开缓存。

## 场景一：托管接入

适合已经有网站、不想在源站里写判定代码的商户。网关站在域名和源站之间，同一条 URL 回源不同内容。

准备：

- 真实网站的源站地址，例如 `https://origin.example.com`。
- 审核内容三选一：商户后台里的平台模板、另一台审核源站、一个静态包。

步骤：

1. 商户端 → 站点管理 → 新建站点。接入方式选「托管接入」。混合接入也可以，后面还能再用接口。
2. 站点配置里填写真实源站。审核内容选上面三种之一并保存。
3. 域名管理 → 添加域名。类型选「托管域名」，填访客要打开的域名。按页面提示把 CNAME 或 A 记录指到网关入口。
4. 点校验，状态变为「已绑定」。未绑定之前网关不会用这个域名。
5. 用无痕窗口打开 `https://你的域名/`。没有归因参数时看到审核内容，地址仍是这个域名。
6. 用带已登记分销码或点击参数的链接再打开。看到真实源站的页面，地址仍是这个域名。同一浏览器关掉参数再访问，仍是真实页。

不要把这个域名同时配成斗篷短链的关联域名。短链会跳走，托管域名要留在当前地址。

自有域名不会走这条回源。自有域名请用场景二或场景三。

## 场景二：WordPress，地址不变

适合要替代 V1「PHP 直接输出 HTML」和「同域双模板」的站点。安装 `wordpress-plugin/cloak-attribution`，不要和旧的 `cloak-api` 同时启用。

准备：

- 站点的服务端密钥 `sk_`。在站点配置页创建或重置，只显示一次。
- 网关地址，即接入指南顶部的网关地址。
- 一套审核内容。真实页面不用另做，默认就是现在的网站。

步骤：

1. 把 `cloak-attribution` 放到 `wp-content/plugins` 并启用。设置 → Cloak 归因。
2. 网关地址填接入指南里的地址。密钥写入 `wp-config.php`，不要写进主题或页面：

```php
define('CLOAK_API_BASE', 'https://网关地址');
define('CLOAK_SECRET', 'sk_xxxxxxxx');
```

3. 点「测试连接」。失败时先看服务器能不能访问网关，以及密钥是不是 `sk_`。
4. 网关不可用时选「显示审核内容」。
5. 审核内容选一种不跳转的方式，见下表。保存。
6. 无痕打开首页，应看到审核内容，地址不变。再用带分销码的链接打开，应看到原来的 WordPress 页面，地址仍是刚刚输入的那条。

审核内容四种不跳转方式：

| 后台选项 | 什么时候用 | 你要准备 | 访客地址 |
| --- | --- | --- | --- |
| 使用平台配置的审核模板 | 审核页在商户后台改，不发 WordPress 版 | 站点配置里选好模板并保存 | 不变 |
| 渲染站内页面 | 审核页是后台的一个页面，但不想把访客带到那个页面的固定链接 | 发布一个页面，在插件里选中它 | 不变。首页仍是首页，正文换成该页面 |
| 输出服务器 HTML 文件 | 审核页是独立 html，可以放在网站目录外 | 服务器上的绝对路径，PHP 可读 | 不变 |
| 服务端拉取外部地址 | 审核页在另一台服务器，但不想浏览器跳走 | 该地址的 https URL | 不变。WordPress 服务器把对方页面取回来再输出 |

排除路径每行一条，例如 `/cart`、`/checkout`、`/blog/*`。这些地址不判定，直接是真实页面。后台、登录、REST、Cron 本来就会跳过。

已登录用户要不要跳过，按店铺情况勾选。店员登录后看真实页面，就勾上。

## 场景三：自研服务端

适合自己的 PHP、Node、Go、Python 程序。在生成 HTML 之前调用判定，再决定输出哪一个文件或模板。地址不跳转。

准备：

- 站点接入方式为「服务端接入」或「混合接入」。
- 域名管理里把访客域名加成「自有域名」。解析仍指向你的服务器，不要指到网关。
- `sk_` 放在环境变量。

步骤：

1. 用接入指南里的签名函数。路径不要带查询串。
2. 每个页面向 `POST /api/open/v2/decision` 提交当前完整 URL、Cookie 里的访客令牌、IP、UA、Referer。
3. 返回里有 `cookie` 就按其中的名字、有效期、域名写入。这一步放行和审核都要做。
4. `content` 为 `real` 或 `bypass`：输出真实模板，结束。
5. 否则输出审核页，HTTP 200，并设置 `Cache-Control: no-store`。按站点配置选用下面一种，不要 302：
   - `renderHint.type` 为 `html`：把 `renderHint.html` 写给浏览器。这是平台模板。
   - 自己的审核文件：读取服务器上的 html 再输出。
   - 审核页在别的机器：你的服务器去请求那个 URL，把正文输出。不要把浏览器重定向过去。
6. 超时或网络错误：输出审核页。

签名和请求体用接入指南「场景一：页面请求判定」里的示例。那里的 PHP 已经包含写 Cookie、输出 `renderHint.html`、否则 `include review.html`。

## 场景四：兼容 V1 的跳转

只在必须换成另一个网址时使用。广告平台、统计和回访都以地址为准时，优先回到场景二。

302 跳转会让浏览器从当前地址再请求一次目标地址：地址栏会从原链接变成目标链接，网络慢时能看到地址切换和一瞬白屏（俗称「闪一下」）。跳转后刷新、复制、分享的都是目标地址，历史里也会多一条记录。因此落地页 SEO 和回访 Cookie 对地址敏感时，不要用这一节。

插件里审核页、真实页都可以单独选跳转。真实页不选时，仍是继续当前页面。

| 后台选项 | 对应 V1 | 发生什么 | 注意 |
| --- | --- | --- | --- |
| 站内页面（跳转） | 方案一，`wp_safe_redirect` | 302 到该页面的固定链接 | 审核页、真实页各跳各的。访客最终不在他输入的地址上 |
| 外部链接（跳转） | 方案二 | 302 到 https 地址 | 只允许 https。主机必须写在白名单。白名单为空则不跳 |
| HTML 地址（跳转） | 方案三 5.5.1 | 302 到文件的公开 URL，例如 `/wp-content/cloak/review.html` | 文件必须能被浏览器直接访问 |

V1 教程里的「方案三-B，PHP 直接输出」和「5.6 同域双模板」不是这一节。它们地址不变，用场景二的「输出服务器 HTML 文件」或「渲染站内页面」。

旧插件 `cloak-api` 已经在线上、暂时不换程序时：把 API 地址指到 V2 的 `POST /api/open/decision`，`X-API-Key` 换成站点 `sk_`。`page` 字段仍在。`ck_` 不能用。插件里的四种模式不用改。

## 场景五：JS SDK

适合没有服务器、审核内容和真实内容可以同时出现在 HTML 源码里的落地页。

1. 页面引入 `https://网关地址/_cloak/sdk.js`，`data-key` 填站点公钥 `pk_`。
2. 放两个区块：`data-cloak="review"` 和 `data-cloak="real"`。
3. 打开页面的域名必须已经绑在这个站点上。

SDK 在浏览器里请求判定，再显示其中一块。查看源代码能看到两套内容。要隐藏真实 HTML，用场景一、二或三。

`data-banner="off"` 关闭内置浏览器里的「在浏览器中打开」提示条。提示条是浮层，不挡住页面上的点击。

## 上线前检查

1. 密钥是 `sk_`，只在服务器配置里，页面源码和 Git 里没有。
2. 无痕、无参数：审核内容。带有效分销码或点击参数：真实内容。同一浏览器再打开无参数链接：仍是真实内容。
3. 地址不变的场景，地址栏与输入一致，响应 200。跳转场景才出现 302。
4. 全页缓存已排除，或按 Cookie 分开。
5. `/wp-admin`、登录、支付回调在排除路径里，打开它们不会变成审核页。
6. 拔掉网关或把密钥改错：前台变成审核内容，而不是把真实页露出来。
7. 商户端「API 调用日志」能看到这次请求。`content` 或 `page` 与页面一致。

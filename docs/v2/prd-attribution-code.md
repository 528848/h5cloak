# 归因码 PRD

## 1. 文档信息

| 项 | 内容 |
| --- | --- |
| 模块 | 归因码（原「分销码」模块，`promo_codes` 表 / `attribution` 域） |
| 文档版本 | v1 |
| 配套 | `docs/v2/technical-design-attribution-code.md` |
| 本阶段 | 统一术语为「归因码」，补齐产品定义与接入说明；只做术语与文档，不改表结构、类型取值与判定引擎 |

## 2. 结论

当前系统里商户登记的「码」已经承担归因职责，但界面、菜单、文档混用「分销码」「活动码」「码」三种叫法，概念不统一。本方案把这一实体在全局统一定名为**归因码**，「分销码」「活动码」降为归因码下的两个**类型**。

用户描述的行为——同一 URL 在有效期内返回真实内容、过期返回审核内容、首访后由 SDK 在浏览器写入凭证、内置浏览器跳系统浏览器时带着凭证——判定引擎已经实现。本方案把它写清楚、对齐叫法，不重做引擎。

## 3. 定义

**归因码**：商户登记的一串字符，用来识别「带来真实访客的来源」。访客通过带归因码的链接访问落地页时，系统据此判定其为真实访客并返回真实内容。

归因码有两个**类型**（`codeType`，取值不变）：

| 类型 | 取值 | 用途 |
| --- | --- | --- |
| 分销码 | `distributor` | 标识分销商 / 推广员，按码统计其带来的访问与转化 |
| 活动码 | `campaign` | 标识一次投放活动 / 渠道活动 |

每个归因码属于一个站点，带：码值、名称、渠道标签、状态、生效时间、失效时间、允许路径、备注，以及访问 / 首访 / 回访 / 转化统计。

## 4. 生命周期与有效期语义

归因码的**展示状态**由「开关状态 + 有效期」共同决定（`EffectiveStatus`）：

| 展示状态 | 条件 | 带该码访问的判定 |
| --- | --- | --- |
| 有效 | 已启用，且当前时间在生效时间之后、失效时间之前 | 命中归因 → 真实内容 |
| 未生效 | 已启用，但当前时间早于生效时间 | 不命中 → 审核内容 |
| 已过期 | 已启用，但当前时间晚于失效时间 | 不命中 → 审核内容 |
| 已停用 | 手动停用 | 不命中 → 审核内容 |

要点：**同一个 URL，带着有效期内的归因码访问返回真实页面；归因码过期、未生效或停用则返回审核页面，地址不变。**这正是「同域双内容」的来源判定部分。

## 5. 访客凭证（浏览器侧身份）

访客首次带有效归因码访问并命中后，系统签发一枚**访客令牌**（站点密钥签名的字符串），由网关或 JS-SDK 写入访客浏览器的 Cookie（默认 `_ck_vid`）。令牌内含访客 ID 与归因 ID，有效期由站点「归因有效期」配置决定。

作用：

- **回访免带码**：令牌有效期内，访客再次打开同一站点的链接（哪怕不带归因码），凭令牌仍判定为真实访客。
- **身份延续**：令牌是后续转化上报、回访统计、跨页识别的依据。
- **续期**：站点可配滑动续期（每次访问重签）或固定到期。

令牌只存浏览器 Cookie，不含明文归因码；服务端用站点密钥验签，无法被伪造。

## 6. 跨浏览器交接（内置浏览器 → 系统浏览器）

微信 / 抖音等 App 内置浏览器里，访客带归因码访问命中真实内容时，系统为这次放行签发一枚**一次性交接凭证**（`_ck`，一次性、限次、限时，存于服务端 Redis，指向同一访客与归因）。

- 内置浏览器页面显示「在浏览器中打开」引导条，引导条里的链接在原 URL 上追加 `_ck`。
- 访客在系统默认浏览器打开该链接，系统消费 `_ck`，把这次访问**接续为同一个归因**（同访客、同归因码来源），返回真实内容并在系统浏览器里同样写入访客令牌。

即：**从内置浏览器跳到系统默认浏览器时，携带的是代表这枚归因码归因的交接凭证**；系统浏览器凭它继续真实内容，而不是把原始码值暴露在链接里。这比直接把归因码明文带过去更安全，归因结果一致。

（可选增强：如商户需要在交接链接上保留可读的归因码用于自有埋点，可在技术方案里以附加参数形式输出，不改变 `_ck` 的归因权威性。本阶段不默认开启。）

## 7. 术语统一

| 原叫法 | 统一为 | 位置 |
| --- | --- | --- |
| 分销码（模块 / 菜单 / 标题） | 归因码 | 商户端菜单、页面标题、弹框标题、按钮、确认文案 |
| 全平台分销码 | 全平台归因码 | 总后台菜单与页面 |
| 「码」「个码」 | 「归因码」「个归因码」 | 汇总卡、确认框、结果提示 |
| 分销码 / 活动码（类型） | 保留，作为归因码的**类型** | 类型下拉、标签 |

说明：类型取值 `distributor` / `campaign`、权限标识 `attribution:code:*` / `platform:code:*`、数据表 `promo_codes`、接口字段 `codeType` 全部不变，只改展示文案，保证兼容与数据不动。

## 8. 验收

1. 商户端左侧菜单显示「归因码」，进入后页面、弹框、按钮、确认框均称「归因码」，不再出现裸「分销码」作为模块名。
2. 类型列仍可选「分销码 / 活动码」，取值不变，历史数据与导出不受影响。
3. 总后台「全平台归因码」菜单与列表文案同步统一。
4. 带有效期内归因码访问同一 URL 返回真实内容；停用 / 过期 / 未生效返回审核内容（引擎既有行为，回归不变）。
5. 首访命中后浏览器写入访客令牌 Cookie；回访不带码仍判定真实（既有行为）。
6. 内置浏览器放行时出现引导条，系统浏览器打开带 `_ck` 的链接接续为同一归因（既有行为）。

## 9. 本阶段不做

不改 `promo_codes` 表结构与 `codeType` 取值，不改权限标识，不改判定引擎与交接机制，不新增把原始码值明文带入交接链接的默认行为。
